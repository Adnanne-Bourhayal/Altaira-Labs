# Provisioning plan visual demo review

## Safety boundary

These previews consume four versioned JSON snapshots generated from the real Engine v2 demo scenarios. `ProvisioningPlanPanel` receives a `previewPlan` prop and does not call a backend route, datasource or provider API. Preview mode disables plan generation, review-state changes and `Confirm and provision`.

- Datasource: none (frontend mock fixtures)
- Neon/PostgreSQL: not used
- Render: not used
- External APIs: not used
- Migrations: not applied
- Environment: development only; every preview route returns 404 when `NODE_ENV` is not `development`

The canonical snapshots live in `lib/provisioning-demo-snapshots`. They are generated by `ProvisioningDemoSnapshotContractTests` from the same scenario catalog, requirement normalizer, decision engine and dry-run provider registry used by the 50-scenario audit. The frontend does not redefine routes, confidence, signals, tools, risks or shared resources.

Before running backend validation, confirm that `DATABASE_URL` and `SPRING_DATASOURCE_URL` are unset. Tests must explicitly use H2 in memory.

## Checklist for every demo

- The header shows the fictional company and sector.
- The track tabs exactly match the expected tracks above.
- Selecting a track shows its route, A3/A2/A1/M level, confidence, signals and explanation.
- Included and excluded tools are separated.
- Track risks and manual steps are visible.
- Cross-track providers appear once under **Shared resources**.
- Planned resources say `PREPARE`; no external ID or URL exists and execution remains blocked until a future approved provisioning phase.
- The blue planning notice says no external resources will be created.
- The review-state control is disabled in fixture mode.
- The top action reads **Fixture preview** and is disabled.
- **Confirm and provision** remains disabled.

## Review findings

The panel has a clear review order: overall plan, required capabilities, track decision, tools, manual work and risks, shared resources, planned resources, then the execution lock. Separating service tracks avoids mixing unrelated recommendations, and shared providers are not repeated in each track.

Potential refinements before migration/deployment:

1. Collapse matched signals after the first four when a real plan contains many signals.
2. Add an optional compact view for long planned-resource and shared-resource tables.
3. Keep confidence visually secondary to the route and explanation; it is not a guarantee.
4. Consider grouping long shared-resource tables only if a real plan exceeds the current four-demo density.

## Snapshot anti-drift workflow

The normal test run compares every committed snapshot with fresh Engine v2 output and fails on any difference:

```bash
cd /Volumes/T7/Altaira_Labs/Altaira_Labs_web/backend
env -u DATABASE_URL -u SPRING_DATASOURCE_URL \
  ./mvnw -Dtest=ProvisioningDemoSnapshotContractTests test
```

When an Engine v2 decision is changed intentionally, regenerate the four files locally:

```bash
cd /Volumes/T7/Altaira_Labs/Altaira_Labs_web/backend
env -u DATABASE_URL -u SPRING_DATASOURCE_URL \
  ./mvnw -Dtest=ProvisioningDemoSnapshotContractTests \
  -Dprovisioning.snapshots.update=true test
```

Review the JSON diff and all four visual routes before accepting it. The generator aborts if `DATABASE_URL` or `SPRING_DATASOURCE_URL` points to Neon, Render or a remote PostgreSQL URL. All registered providers are also asserted to be dry-run only.

## Validation boundary

Frontend validation:

```bash
npx tsc --noEmit
npm run lint
npm run build
```

Backend validation with an explicit H2 datasource:

```bash
cd backend
env -u DATABASE_URL -u SPRING_DATASOURCE_URL \
  SPRING_DATASOURCE_URL='jdbc:h2:mem:altaira_demo_validation;MODE=PostgreSQL;DB_CLOSE_DELAY=-1' \
  SPRING_DATASOURCE_USERNAME=sa SPRING_DATASOURCE_PASSWORD= \
  ./mvnw test

env -u DATABASE_URL -u SPRING_DATASOURCE_URL \
  SPRING_DATASOURCE_URL='jdbc:h2:mem:altaira_demo_package;MODE=PostgreSQL;DB_CLOSE_DELAY=-1' \
  SPRING_DATASOURCE_USERNAME=sa SPRING_DATASOURCE_PASSWORD= \
  ./mvnw package -DskipTests
```

These commands do not apply `backend/database/provisioning-engine-v2-visibility-migration.sql`.
